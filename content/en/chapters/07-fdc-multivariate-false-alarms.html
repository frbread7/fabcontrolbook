Multivariate Monitoring, Fault Detection, and False Alarms

Learning objectives

This chapter develops a disciplined interpretation of multivariate monitoring for semiconductor equipment and process data. You will distinguish detection from diagnosis, explain why correlated variables can add useful evidence while complicating thresholds, and design an evaluation that exposes false alarms, missed events, and context dependence. A monitor is useful only when its statistical behavior and engineering response are understood together.

Start with a data record that identifies tool, chamber, recipe and revision, wafer/lot, operation, sensor identity and calibration, time basis, maintenance state, and any relevant metrology result. Preserve these contextual keys through joins and feature generation. Missing context can create a convincing but spurious multivariate pattern.

Core concepts

For a centered feature vector x of dimension p and a covariance estimate Σ, Hotelling's squared distance is T² = (x − μ)ᵀΣ⁻¹(x − μ). It accounts for feature scales and correlations: a combination unusual relative to the covariance structure may be flagged even if each feature alone appears ordinary. Inverting an ill-conditioned or singular covariance matrix is unstable; many correlated sensors, short baselines, and constant features are common causes. Reduce redundant dimensions, regularize with a stated method, or use a physically motivated feature set.

Under independent multivariate normal observations and a fixed model, theoretical thresholds can be derived for specified false-alarm probabilities. In practice, observations may be autocorrelated, baseline estimates uncertain, and recipe populations mixed. Therefore, a nominal tail probability is not a guaranteed field false-alarm rate. Calibrate against held-out runs grouped by time, lot, or tool, and report alarms per run or wafer plus event-level detection delay.

Principal-component monitoring separates variation along learned directions from residual variation. A score statistic such as T² measures distance in retained components; a residual statistic such as squared prediction error measures what the model does not explain. These are complementary views, not physical diagnoses. Components can rotate when the training population changes. Record training revision, centering/scaling, retained rank, feature definitions, and operating contexts.

Detection means evidence that an observation is inconsistent with a reference model. Classification assigns a label based on a learned or specified mapping. Diagnosis proposes a physical explanation and needs corroboration: event logs, sensor checks, tool state, process signatures, and wafer results. A classifier's confidence is conditional on its training data and class definitions; an unknown fault can be confidently assigned to a familiar but wrong class.

False alarms may arise from drift, maintenance, recipe transitions, unmodeled product mix, sensor recalibration, or data pipeline defects. Missed detection can follow from insensitive features, overly broad baselines, delayed sampling, or faults outside the learned envelope. These outcomes have different costs. Establish intended use, action owner, escalation timing, and alarm suppression policy before tuning a threshold.

Worked example

Use two centered synthetic features with covariance Σ = [[1, 0.5], [0.5, 1]] and observed vector x = (2, 1). Since Σ⁻¹ = (1/0.75)[[1, −0.5], [−0.5, 1]], T² = xᵀΣ⁻¹x = (4 − 2 + 1)/0.75 = 4. For a fixed known bivariate normal reference, an illustrative 5% upper-tail χ²₂ threshold is 5.991, so this point does not signal. This threshold is a textbook large-sample/known-parameter illustration, not a validated fab limit; estimated covariance, serial dependence, and baseline selection require design-specific calibration.

Separately, suppose a predeclared operational threshold evaluated on a synthetic chronological holdout yields 500 nominal runs and 20 independently labeled excursion runs: 21 false-positive runs, 479 true negatives, 5 detected excursions, and 15 missed excursions. Thus precision among flags is 5/26 = 19.2%, event recall is 5/20 = 25%, and false-positive burden is 21/500 = 4.2% of nominal runs (or 4.2 false-positive runs per 100). These counts are an illustrative confusion table and are not asserted to be the preceding χ² threshold’s measured performance. Multiple channels or repeated windows create multiplicity; count the run as the operational unit and calibrate the full alarm policy on held-out groups. An anomaly flag means inconsistency with a reference model, not identification of a physical fault or proof of product failure.

Limitations and cautions

Multivariate methods depend on representative data, stable feature transformations, and correctly identified contexts. Covariance estimates degrade when feature count is large relative to independent runs. Class imbalance makes raw accuracy misleading. Evaluation must include false-positive burden, missed excursion modes, and time-to-detection. Threshold tuning on the final test set invalidates an unbiased performance claim.

Do not equate correlation with process causality. A feature can predict a fault because it records a consequence, an operating mode, or a confounder. Before an automatic containment or control action, assess intervention risk, sensor failure modes, delay, fail-safe behavior, and human override. This educational framing is not a validated factory monitor.
