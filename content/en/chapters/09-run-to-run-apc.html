Run-to-Run APC and EWMA Controller Mathematics

Learning objectives

Run-to-run (R2R) advanced process control adjusts recipe inputs between completed lots or wafers, using delayed metrology or equipment measurements to compensate for disturbances. This chapter develops the basic EWMA controller, explains its assumptions and stability trade-offs, and connects its output to constraints, measurement lineage, and human governance. The controller is a model-based decision aid; its existence does not make an unqualified process safe for automatic correction.

For every control update, retain the input lot/wafer, tool and chamber, recipe revision, measured response, metrology timestamp and calibration, controller state, selected recipe, constraint status, operator approval, and resulting run identifier. A delayed result must never be silently assigned to the “latest” run if intervening lots were processed.

EWMA R2R model

For a memoryless scalar teaching plant, let the physical output be xk = c₀ + b uk + δk and the observed result be yk = xk + ηk. Here u is the input applied to run k, b has response units per input unit, δ is an output-unit disturbance, and η is measurement error. The constant c₀ is an offset, not the lab's plant-memory parameter a. This is a local approximation over a defined operating range, not an identified fab plant.

After a result becomes available, form signed target error qk = ytarget − yk and q̄k = λqk + (1−λ)q̄k−1, with 0 < λ ≤ 1. This filters a correction residual; it is not a measured physical disturbance. With an immediately available result, the next-run command is uk+1 = uk + Kq̄k. Positive bK gives the correcting sign: a high output creates negative q and lowers the next input. The sign and magnitude of a real plant gain require a safe, approved identification experiment.

Exact no-delay special case. For constant c₀+δ, zero measurement noise, no saturation, and λ=1, the error obeys xk+1−ytarget = (1−bK)(xk−ytarget). It converges asymptotically only when |1−bK|<1, or 0<bK<2. The boundary bK=2 alternates without decay. This condition does not cover filtering, plant memory, metrology delay, extra actuation delay, noise, or clipping.

Lab run convention. Its separate normalized plant uses x[k]=a x[k−1]+(1−a)(δ[k]+u[k−1−da]), with output memory a, unit positive plant gain, and da extra actuator-run delay. The result y[k]=x[k]+η[k] is produced after run k; with metrology delay m, only y[k−m] is available at that decision. The EWMA and bounded command update then use that source run; before the first result the command is held. A computed u[k] cannot affect run k. The analytical b=2 example below and this unit-gain lab are deliberately different normalizations.

Small λ smooths noise but adapts slowly to a step disturbance. Large λ responds faster but passes more noise into recipe movement. Increasing controller gain can shorten correction time yet cause oscillation or amplify metrology noise, especially with delay. Delay means the measured outcome may correspond to an older recipe; the controller must preserve run association and queue updates safely. Missing or out-of-order measurements should hold the controller state and raise a data-quality condition, not trigger an invented value.

Bounds are part of the design: umin ≤ uk ≤ umax, maximum change per update, slew rate, and process safety limits. Saturation can leave residual error and invalidate the assumed linear compensation. Anti-windup or state reset rules must be defined when the internal estimate continues moving while the actuator is at a bound. The command must remain in an approved recipe envelope; assess predicted and measured product responses against their specifications separately. Specifications are not substitutes for equipment-safe operating limits.

For multivariable processes, response and recipe vectors relate through a gain matrix y = A u + d. Poorly conditioned or unidentified A makes inverse correction risky. Identify the model with designed, safe perturbations and estimate uncertainty; do not infer causality from observational correlations alone. Feedforward uses a disturbance measurement available before the outcome; feedback uses measured response after processing. Their latency and failure modes differ.

Worked example

Use a synthetic memoryless plant with target 0, c₀=0, b=2 response units/input unit, no delay or noise, and a +1 response-unit step from run 5. Set u₅=0, q̄₄=0, λ=0.5, and K=1/b=0.5 input units/response unit. Compute output, signed filtered error, and the command for the next run in that order:

On a narrow screen, swipe the table or focus it and use arrow keys. The output sequence 1, 0.5, 0, −0.25, −0.25 crosses target and is not monotone in absolute error. Under these constant, unsaturated assumptions, the two-state recurrence has characteristic polynomial r²−r+0.5=0, with roots 0.5±0.5i of magnitude √0.5<1: this particular filtered loop is asymptotically damped yet oscillatory. That result does not transfer to delayed, saturated, or misidentified plants.

Now delay each metrology result by one run. At the end of run 5 the available result still belongs to run 4, so its zero error leaves the run-6 command unchanged; at the end of run 6 the run-5 result arrives and can first change the run-7 command. An extra actuator delay is a different queue: the result can arrive now while the newly computed command affects a later run. The lab lets the two delays vary separately and identifies which source run updated the controller. Compare output, input movement, and saturation under a declared seed and noise level (for example 0.2 response units); do not treat a finite simulation trace as a general stability proof or a production performance estimate.

Before deploying even a bounded controller, verify gain sign and magnitude in the relevant operating region, simulate disturbances and missing metrology, assess saturation, define manual hold and rollback, qualify the metrology route, and independently review recipe limits. Use staged authorization and monitor post-update outcomes. Statistical control limits indicate process behavior; product specifications and equipment safety limits govern different decisions.

Limitations and engineering safeguards

EWMA R2R assumes sufficiently stable gain, valid run matching, a meaningful target, and a disturbance model appropriate to the process. Autocorrelated metrology errors, multiple interacting inputs, recipe transitions, and maintenance resets can invalidate simple calculations. An apparently stable output may be achieved by increasingly extreme input moves, so monitor both output and actuator trajectory.

Never use this educational model as a recipe recommendation for real wafers. Production use requires process-owner approval, safe designed experiments, model validation, equipment interlocks, cybersecurity and change controls, traceability, fail-safe behavior, and a human disposition process. No silicon or fab validation is claimed here.

Review questions

  1. State the assumptions in the scalar linear R2R model and explain when local gain is inadequate.
  2. How does λ trade noise rejection against response to a step?
  3. Why must each delayed metrology result map to its actual processed run?
  4. What happens when recipe input saturates, and what anti-windup policy would you specify?
  5. Distinguish control limits, product specifications, and equipment-safe bounds.
