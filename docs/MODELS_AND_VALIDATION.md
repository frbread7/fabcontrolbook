# Quantitative models and validation status

All four labs use generated synthetic data. Internal statuses below describe the work actually done in code and tests; none means calibration against an industrial process or validation on silicon.

## A. SPC detection performance

Observations are standardized: `z[t] = μ[t] + σobs·ε[t]`, where `ε` is generated standard normal, baseline sigma is assumed known and equal to 1, and the injected mean is 0 before a fixed change point. The post-change mean is a step or a finite linear ramp. The three chart statistics are:

- Shewhart: signal when `|z[t]| > 3`.
- EWMA: `E[t] = λ z[t] + (1−λ)E[t−1]`, initialized at 0; time-varying limit `L·sqrt(λ/(2−λ)·(1−(1−λ)^(2t)))`, with `L=3`.
- Two-sided tabular CUSUM: `C+[t]=max(0,C+[t−1]+z[t]−K)` and `C−[t]=max(0,C−[t−1]−z[t]−K)`, with `K=0.5`, `h=5`.

The UI varies shift, observed noise scale, EWMA weight, horizon, profile, and seed. The chart settings are fixed comparison parameters, not tuned to equalize in-control average run length. When observed noise differs from 1, the simulation intentionally creates a variance mismatch against limits fixed to the known baseline σ=1; this changes false-alarm probability and is part of the comparison. The false-alarm metric is the probability of one or more signals anywhere in the full matched-duration no-shift baseline horizon; it is not restricted to the pre-change portion of a shifted trial. Independent Gaussian samples, a known baseline, fixed parameters, and no restart/hold policy are assumptions. False-alarm and detection rates are finite-horizon Monte Carlo proportions, not ARL estimates. The UI reports 95% Wilson intervals for the binomial proportion across trials; these do not include model or parameter uncertainty. Median detection delay is a descriptive point summary conditional on trials that signaled after the change; it has no uncertainty interval. For event count `x` among `n` trials, the displayed interval uses `p=x/n`, `z=1.96`, denominator `1+z²/n`, center `(p+z²/(2n))/(1+z²/n)`, and half-width `z·sqrt(p(1−p)/n+z²/(4n²))/(1+z²/n)`, bounded to [0,1]. Validation: formulas are cross-checked against the NIST handbook; tests independently calculate chart recurrences, signal times, Wilson limits, and finite-horizon rate/delay summaries and establish deterministic repeatability and boundary rejection. **Status: analytically checked and numerically deterministic; no process validation.**

## B. FDC signal intelligence

Four fixed recipe phases each have 20 normalized sample points in three synthetic channels. Phase means and the reference standard deviation `σref = 0.08` are declared in code; traces use a fixed-seed normal generator. For each channel within each phase, the lab computes (1) a known-variance mean statistic `z̄ = (x̄−μref)/(σref/√n)`, (2) a normal-theory approximate dispersion statistic `zs ≈ (s−σref)/(σref/√(2(n−1)))`, and (3) an OLS slope statistic `zβ = β̂/(σref/√Sxx)` for the observed sample indices. The latter assumes a linear trend plus iid Gaussian noise with known standard deviation. Each phase's statistical score is the largest absolute feature statistic; the selected threshold is applied separately to each statistical feature. Missingness and phase-context mismatch are independent data-quality flags and are reported separately. The scenarios inject a pressure offset, flow oscillation, process ramp, missing flow segment, or phase-context mismatch.

This transparent rule is not a trained classifier or a calibrated control limit. Testing many correlated features across channels and phases inflates the chance of at least one false flag; no multiplicity adjustment is implemented. Missingness/context flags mean the record needs review, not that the process is faulty. Real deployments require phase alignment, data-quality states, contextual baselines, calibration, fault-label quality, correlated-feature treatment, and site-specific false-call evaluation. Validation: fixed-seed traces; tests independently calculate mean, approximate dispersion, and OLS slope statistics; deterministic injected-signature checks; invalid scenario and threshold tests. **Status: analytically checked synthetic feature calculations; no equipment fault validation.**

## C. Run-to-run APC

The normalized output follows `x[k] = a·x[k−1] + (1−a)·(d[k] + u[k−1−d])`, with a positive unit process gain, output target 0, first-order memory `0≤a≤0.9`, and a step disturbance at 30% of the run sequence. Measurement is `y[k]=x[k]+η[k]`, where `η` is seeded normal noise. The correction estimate is `eEWMA[k]=λy[k]+(1−λ)eEWMA[k−1]`; the next action is `u[k]=clip(u[k−1]−Kc·eEWMA[k],−Umax,Umax)`. Here `d` is an additional actuation/run delay beyond the unavoidable measure-then-update sequence. The action is normalized and does not represent a recipe parameter or physical unit.

Assumptions: constant known control direction/gain, fixed first-order run model, zero target offset, one persistent disturbance, no product/chamber coupling or metrology delay beyond the modeled run queue. The tested gain is not claimed stable across all combinations. Validation: zero-disturbance and zero-gain limits, an independent nonzero-gain recurrence check, the corrective-action sign under a positive disturbance, actuator saturation, delay-queue checks, deterministic output, and finite-value tests. **Status: selected analytical recurrence checks and numerical edge tests; no identified-plant or factory validation.**

## D. Manufacturing alarm strategy

Each channel is `zᵢ[t]=sqrt(ρ)c[t]+sqrt(1−ρ)εᵢ[t]+δᵢ[t]`, with independent standard normal common and channel draws, yielding unit variance and pairwise correlation `ρ` under the stated equicorrelation model. A channel exceeds if `z>τ`. The vote rule is one-of-n, strict majority, all-of-n, or a valid integer threshold. An alarm occurs after at least `m` consecutive samples satisfy the vote rule. A synthetic positive shift is added to channel zero after a known change point. Rates are estimated over independent no-event/event trials and a finite observation horizon.

This event detector does not include alarm shelving, acknowledgements, deadbands, state-dependent inhibits, resource queues, or overlapping alarm episodes. Pre-change alarms stop a trial and do not count as successful event detection. The UI reports 95% Wilson intervals and the trial count for finite-trial false-alarm and detection proportions; these do not cover model or parameter uncertainty. Median and mean detection delays are descriptive point summaries conditional on detected event trials and have no uncertainty interval. Validation: independently calculated seeded summaries cover the `ρ=0` independent limit, correlated common-factor samples, 1-of-1 logic, persistence reset, threshold direction, and false-alarm/detection delay aggregation; invalid vote rules are rejected. **Status: analytically checked covariance and alarm logic; finite Monte Carlo only, no human-factors or fab validation.**

## Shared validity limits

The code is plain JavaScript with no runtime service. Seeds are explicit. Inputs are bounded; no external data is fetched. A passing suite confirms source behavior and implementation cases only. Chart false-alarm tradeoffs, classifier thresholds, controller stability, chamber sensor meanings, production action bounds, and operator alarm practices require local data, approved control plans, and responsible engineering review before any real use.
